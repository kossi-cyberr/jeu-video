Installation et compilation

Prérequis, commandes Gradle, APK Android et version bureau

Version 1.0.0 Auteur : Kossi Novembre 2026

1. Prérequis

BesoinVersionUsage
JDK17 ou plusCompiler core, lwjgl3 et android
GradleFourni (wrapper 9.8)Aucune installation : utiliser ./gradlew
Android SDKAPI 36 + outils de buildUniquement pour produire l'APK
Python 3 + Pillow3.8+Uniquement pour régénérer les images et les sons
Sans Android SDK, tout le reste fonctionne : les tests unitaires et la version bureau n'ont besoin que du JDK.

2. Récupérer le projet

git clone https://github.com/kossi-cyberr/jeu-video.git
cd jeu-video/Moto-Taxi-Rush

Le dépôt contient les sources, les assets et la documentation. Aucun fichier de build n'est versionné : tout se régénère.

3. Commandes essentielles

CommandeEffet
./gradlew :core:testLance les 22 tests unitaires
./gradlew lwjgl3:runLance le jeu dans une fenêtre de bureau
./gradlew android:assembleDebugProduit l'APK de test
./gradlew lwjgl3:distFabrique un jar exécutable dans lwjgl3/build/libs/
./gradlew cleanEfface tous les dossiers de build

Détail : tests

./gradlew :core:test

BUILD SUCCESSFUL
Rapport detaille : core/build/reports/tests/test/index.html

Détail : version bureau

./gradlew lwjgl3:run

La fenêtre s'ouvre en 480 × 800. Sur une machine sans affichage (serveur, SSH sans redirection X), cette commande échoue : c'est une limite de la bibliothèque graphique, pas du jeu. Utiliser un poste avec écran, ou exporter la variable DISPLAY vers un serveur X actif.

Détail : APK Android

./gradlew android:assembleDebug

APK produit :
android/build/outputs/apk/debug/android-debug.apk

Le script copyAndroidNatives s'exécute automatiquement avant la compilation : il extrait les bibliothèques natives de libGDX dans android/libs/<abi>/. Ces dossiers sont ignorés par Git, ils sont recréés à chaque build.

4. Installer sur un téléphone

4.1 Par câble USB

  1. Activer le mode développeur et le débogage USB sur le téléphone.
  2. Brancher le téléphone, accepter l'autorisation de débogage.
  3. Installer :
adb install -r android/build/outputs/apk/debug/android-debug.apk

4.2 Par fichier

  1. Copier l'APK sur le téléphone (câble, cloud, messagerie).
  2. Ouvrir le fichier depuis le gestionnaire de fichiers.
  3. Autoriser l'installation depuis cette source si Android le demande.

4.3 Compatibilité

ÉlémentValeur
Android minimum7.0 (API 24)
ArchitecturesARM 64 bits, ARM 32 bits, x86 64 (émulateurs)
OrientationPortrait verrouillé
PermissionsAucune (jeu entièrement hors ligne)

4.4 Désinstaller

adb uninstall cm.motorush.android

Cela efface aussi le meilleur score et le réglage du son, stockés dans les préférences de l'application.

5. Régénérer les assets

Les images et les sons ne sont pas dessinés à la main : ils sont produits par script. Deux commandes suffisent.

5.1 Sprites et sons

python3 tools/generate_assets.py

Régénère la moto, les voitures, le camion, les nids-de-poule, les passagers, le cœur, ainsi que la musique et les bruitages. Les fichiers produits sont identiques à chaque exécution (aucun aléatoire non fixé).

5.2 Médaillon photo du menu

python3 tools/make_portrait.py

Recadre tools/portrait_source.jpg en médaillon rond de 320 px : buste détouré, fond flouté et assombri, anneau orange. La photo source n'est pas embarquée dans le jeu ; seul le médaillon l'est.

Après régénération, relancer ./gradlew android:assembleDebug pour que l'APK contienne les nouveaux fichiers. La tâche assets.txt est recalculée automatiquement à chaque build.

7. Structure d'un build

build/                      sorties Gradle communes
core/build/                 classes compilées et rapports de tests
lwjgl3/build/libs/          jar exécutable (tâche dist)
android/build/outputs/      APK debug
android/libs/               natives extraites (ignorées par Git)

Ces dossiers sont exclus du versionnement : un clone propre ne contient que du code, des assets et de la documentation.
